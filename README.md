# SocialCard

SocialCard is a JavaFX desktop application for writing HTTPS links as NFC URI records to an NTAG215-compatible card through a PC/SC reader.

## Requirements

- JDK 25, with `JAVA_HOME` pointing to the JDK installation and its `bin` directory on `PATH`.
- Apache Maven 3.9 or later.
- A compatible PC/SC NFC reader and its operating-system driver.
- An NTAG215-compatible card with writable user memory for writing links.

JavaFX 27 requires JDK 25 or later. Maven downloads the JavaFX libraries for the current operating system. The project targets Java 25 and does not enable preview features.

## Run and test

From the project directory, run:

```shell
mvn test
mvn javafx:run
```

The automated tests use simulated card communication and do not require a connected reader. The presentation tests initialize JavaFX and require a graphical desktop session. Physical reader compatibility and interrupted writes must also be checked with the actual hardware.

## Supported content

Only absolute HTTPS URLs are accepted. Each link becomes an NFC URI record. NFC applications and phones can handle multiple URI records differently; a single landing-page link provides the most predictable way to present several social profiles.

The application checks the encoded data against the supported card's capacity before writing. Other card types and protected or locked memory are outside the supported writing scope.

Keep the card on the reader until writing and verification finish. Removing the card, losing power, or disconnecting the reader can leave incomplete data. NFC writes are not transactional, and rollback cannot be guaranteed after an interruption.

## Build a native Windows executable

The `native` Maven profile builds a Windows x64 executable with GraalVM Native Image. JavaFX and the JDK PC/SC bridge are linked into the executable. The target computer does not need Java installed. It needs Windows, the NFC reader's normal PC/SC driver and the [Microsoft Visual C++ x64 Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist).

Build requirements:

- Oracle GraalVM for JDK 25, version 25.4 or later, with `JAVA_HOME` pointing to that installation. Its `bin` directory must precede other Java installations on `PATH`.
- Visual Studio 2022 Build Tools with the **Desktop development with C++** workload, the x64 MSVC compiler and a Windows SDK. GraalVM recommends version 17.13.2 or later.
- Maven 3.9 or later, Windows x64, and a graphical desktop session for the tests.

Open an **x64 Native Tools Command Prompt for VS 2022**, configure `JAVA_HOME` and `PATH`, then run from the project directory:

```shell
mvn -Pnative clean package
```

The distributable is `target/SocialCard-windows-x64.zip`. Extract the complete archive and start `SocialCard.exe`. Keep the accompanying DLLs together with the executable. The small `java.dll` and `jvm.dll` files are native forwarding libraries generated by GraalVM, not a JVM. The JavaFX image fallback uses the other native support libraries. Do not rename the executable, as these libraries refer to its name.

The build runs the regular test suite before compiling the native executable. Maven downloads the [Native Build Tools plug-in](https://graalvm.github.io/native-build-tools/latest/maven-plugin.html) and [StaticFX](https://github.com/HebiRobotics/jfx-static-feature) support for JavaFX 27; Maven does not install GraalVM or the C++ compiler itself. Native Image fallback is disabled, so a successful build produces a native executable rather than a Java launcher. The `compatibility` CPU target avoids requiring newer x64 instruction sets.

The native profile contains the GraalVM feature in `src/native/java` that links `j2pcsc` and the Windows smart-card API. Reflection and resource metadata are under `src/main/resources/META-INF/native-image`. Keep that metadata in sync with FXML changes. GraalVM hosted APIs can change between releases; validate upgrades with the check below.

To verify the built executable without connecting to or changing a card, run:

```powershell
$process = Start-Process -FilePath .\target\SocialCard.exe `
    -ArgumentList '--verify-native target\native-verification.txt' `
    -WindowStyle Hidden -Wait -PassThru
$process.ExitCode
Get-Content .\target\native-verification.txt
```

The check verifies the explicit and default PC/SC providers, lists readers, loads and renders the JavaFX interface with a simulated reader service, and confirms a message reaches the log file. The report must end with `Result: PASS`; exit code zero indicates success. Wait for the GUI executable to exit before inspecting the report. Reader enumeration requires the Windows Smart Card service. This check does not verify actual NFC card communication, which requires a separate hardware test.

## Logging

SLF4J uses Logback for both application runs and tests. The default level is `INFO`. The Windows GUI executable writes logs to `%LOCALAPPDATA%/SocialCard/logs/socialcard.log`, retaining three rotated files of up to 10 MB each. When `LOCALAPPDATA` is unavailable, the base directory is the user's home directory. JVM runs also log to the console. Override the directory with the `socialcard.log.dir` system property; tests use `target/logs`.

Logging configuration is in `src/main/resources/logback.xml`. Operational logs should describe reader state and write outcomes without including the submitted URLs.
